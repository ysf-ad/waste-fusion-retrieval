# Benny paired vision pilot

Use this pilot to compare Jev 1.14, Liquid d1.2-ultra, and Liquid d1.2 on the **same revised exact policy**. Artificial Analysis Decision Index does not measure this kiosk's accuracy or photo-to-result latency. A historical baseline is a separate arm: run the frozen old Jev release on the same labels/images to isolate the policy change; do not use old results on different photos as a head-to-head score.

1. Collect up to 20 consented or suitably licensed cases per run. Include hands/fingers/faces with no separate item, a clearly held item, contrasting real cigarette butts and lookalikes, wood fragments, ordinary recycling/garbage, an empty view and ambiguous/multiple items. Freeze labels independently, using applicable Toronto rules for any expected bin. No authentic remains or identifying photos of bystanders. Hold out fresh photos before any tuning.
2. Use the local `prepare_inference_jpeg` helper in `frontend/inference_image.py` on each photo. Keep original and prepared files out of Git; the manifest paths are relative to the manifest directory. Hash each prepared JPEG and then hash the manifest itself. See `manifest.example.json` for the format; placeholders are not a frozen dataset. A null bin means **no bin should be shown**. Expected item may be omitted if policy correctness, not exact catalog wording, is being scored.
3. Dry-run: `node benchmarks/benny-vision/run.mjs PATH_TO_MANIFEST FROZEN_SHA256`. This verifies input hashes and calculates the maximum number of sends and a deliberately high reservation based on documented context ceilings. The reservation is not a quote or an enforced provider spending cap; set a provider-side cap/credit limit as well. No network or credentials are used for the dry-run.
4. Only after explicit budget approval and provider credentials are supplied securely, append `--live NEW_LEDGER.jsonl APPROVED_RESERVE_USD`. Keep both `LIQUID_API_KEY` and `TYPESAFE_API_KEY` in environment variables, never the manifest or logs. The ledger is exclusive and synced before each send; a partial run may have been billed. Do not retry/resume it. Compare false bins before overall correctness, then p50/p95 latency, errors/timeouts, and observed spend plus unknown usage. This runner measures the local Worker handler plus real upstream calls, not camera countdown, Pi, kiosk rendering or Cloudflare edge latency.
5. For staging the real Pi, use a private/rate-limited Worker, set its server-side `DECISION_PROVIDER` to `d1.2-ultra`, add `LIQUID_API_KEY` through the Worker secrets interface, and set `PREPARE_INFERENCE_IMAGE=true` in the Pi service environment. This forwards a bounded EXIF-normalized baseline JPEG to inference while keeping original captures and UI photo blobs intact. Cleanly roll back to Jev by changing only staging configuration; never add an automatic second-provider retry. Production remains Jev until a paired pilot and on-device canary pass.

- Liquid API: https://docs.liquid.ai/lfm/models/d1.md#image-inputs
- TypeSafe API: https://docs.typesafe.ai/images.md
